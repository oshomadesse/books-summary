# 設計記録

この文書を設計判断の正本として管理する。ライフサイクル10要素（0〜9）を上から順に埋めれば設計が完成する問診票とする。
完成条件: すべての成果・評価が最低1つの Reality Anchor（2. State）に接続していること。接地していないグラフは未完成として扱う。

## 0. Purpose

読書習慣の定着と知識インプットの自動化。毎朝1冊、実在の本のサマリーと図解を人間の手を介さず届け、蓄積した書籍ノートを Obsidian のグラフとして繋いで「読んだ本が資産として連携する」状態を保つ。

| 主指標（最適化する） | カウンター指標（犠牲にしない） | 許容範囲 |
|---|---|---|
| 毎朝の通知到達率（Discordに今日の一冊が届く日の割合） | 内容の正確さ（捏造ゼロ。Web で確認できた情報のみ） | 到達率は月2回まで欠落許容。捏造は許容ゼロ |
| 書籍ノートの相互リンク数（グラフの連結） | 誤リンク（別の本を同一と誤認して繋ぐ） | 誤リンクは発見次第即修正。迷ったら繋がない |

Goodhart対策: リンク数を追って類似度の閾値を緩めない。「迷ったら繋がない」が常に優先。

- 改訂できるのは **9. Human** のみ。

## 2. State

| State | 場所 | 性質 |
|---|---|---|
| 既読リスト（唯一の正・append-only） | `state/books_read.json` | Routine が毎日1件追記。削除しない |
| 当日メタ | `state/latest.json` | 上書き。通知 Action と逆リンク処理が読む |
| 書籍ノート | 生成時 `state/inbox/`（リポ内）→ pull 後 vault `100_Inbox/Books-YYYY-MM-DD.md` へ移送 | 移送後は Obsidian が正。リポには残らない |
| 図解HTML | `state/infographics/`（マスター）→ GitHub Pages（Actions 配信） | append。過去URLは不変 |
| バックフィル台帳 | `state/backfill/decisions.json` ＋ `state/backfill/backup/` | 一括リンクの判定記録と適用前バックアップ |
| 旧システム遺物 | `src/legacy/`・`state/legacy/` | 参照のみ。実行されない |

checkpoint: git の各コミットが checkpoint。ノート一括編集（バックフィル apply）は実行前に `state/backfill/backup/<UTC>/` に全対象ファイルをコピーしてから書く。復元はそのコピーを書き戻す。

| pull.log の「✅ pull 成功」 | launchd 実行ログ | 障害時の一次証跡 |

## 4. Edge

- Routine → Actions: `state/latest.json` を含む push（paths フィルタ）。`[skip ci]` を付けると通知が死ぬので Routine のコミットでは禁止
- Actions 内: deploy 成功 → notify（needs:）。Discord 送信失敗で workflow 失敗（LINE は 2026-07-25 完全撤去）
- pull → 移送 → 逆リンク: pull 成功時のみ post_pull が走る。移送コミットは `[skip ci]` 付き（通知を発火させない）
- ボタン → ハンドラ: custom_id `bookdetail:<date>` / `bookmodal:<date>` / `bookconfirm:<date>` / `booksearch` / `booksearchmodal`。デーモン（.discord-daemon）が `.nexus.json` の名札でこのリポの handler に委譲
- ✅確認 → 図解URL解決: ローカル `state/latest.json` → GitHub raw の `state/latest.json`（timeout 2.5秒）→ vault ノートの順。クラウド push（07:26 の実績あり）がローカル pull（07:20）に間に合わない日でも押した瞬間に最新へ届く。vault ノートを最後に置くのは、ノートが iCloud 退避されている日に hydrate が最大60秒ブロックし Discord の3秒制限を超えるため

## 5. Judgement

| 分岐 | 条件（機械が即決） | 判定者 |
|---|---|---|
| 多重実行防止 | books_read.json に今日の date があるか | Routine（`.claude/skills/daily-reading/SKILL.md` 冒頭） |
| 移送時の同名衝突 | `cmp -s` で同一なら repo 側削除、異なればskip+ログ | pull スクリプト |
| 逆リンクの冪等 | セクション内に `[[Books-<date>` が既にあるか | backlink_books.py |
| 未pushコミット回収 | `rev-list origin/main..HEAD` > 0 なら rebase 経路 | pull スクリプト |
| バックフィル自動判定 | 正規化タイトル一致 or（部分一致∧著者一致）で auto | backfill_links.py scan |
| 図解URLのフォールバック段選択 | 各段の date が要求 date と一致するか（不一致なら採用せず次段へ。前日のURLを返さない） | discord_books.py の confirm_details |

- 即決できない照合（表記ゆれ・翻訳違いの同一書判定）は Judgement にせず LLM（Routine Step 4.5 / バックフィルは Sonnet 判定）へ回す。

## 6. Loop

| ループ | 戻り先 | 上限 | 出口 |
|---|---|---:|---|
| Routine push reject | pull --rebase → push | 3 | Routine 実行履歴＋通知欠落で発覚 |
| pull fetch/merge 失敗 | 30秒待って再試行 | 5 | pull.log（翌回で自己回復） |
| 移送コミット push 失敗 | rebase → push | 3 | pull.log（次回の未push回収で自己回復） |
| Pages 反映待ち | 10秒ポーリング | 12 | warning で続行（通知は出す） |

checkpoint 復元はどのループでも不要（全て追記型・再実行で収束する設計）。同時発火なし。

## 7. Verification

- 構築時（本移行作業）: FABER の実装を NEXUS がレビューし、バグ1件（scan の既リンク除外漏れ）を差し戻し修正させた。逆に FABER は仕様に対する実装の自己検証（py_compile・bash -n・dry-run）を実施
- 日次運用: Routine の生成物は Reality Anchor（Pages 200・Discord 2xx・pull.log）で機械検証される。内容品質（捏造・誤リンク）は 9. Human の目視が最終関門
- バックフィルの曖昧判定は作り手（scan スクリプト）と別系の Sonnet が judge し、適用前に NEXUS が抜き取り検証する
