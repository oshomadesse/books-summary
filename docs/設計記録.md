## 7. Verification

Verification（検証）＝決めた基準どおりに作れたかを裁く。基準そのものの正しさは裁かない（それは 9. Human の Validation）。

3rd party（作り手Agentと別モデルまたは独立評価系）による最終関門のみを記録する。自己採点は不可。

合格判定には最低1つの Reality Anchor（2. State 参照）を証拠に含める。AIの自己申告のみで合格させない。

評価に使うデータ・基準は作り手Agentが書き換えられない場所（append-onlyの正本、または作り手のスコープ外）に置く。

（記入）

- 既定: FABER（codex exec / gpt-5.6-sol、OpenAI）。作り手がClaude系Agentの場合、ベンダーごと分離されるため独立性が最も高い。FABERはgit操作不可（sandbox）だが、評価者は読む・裁くだけで書き込まないため制約にならない。むしろ成果物を書き換えられないのは望ましい性質。
- 重要度が高いverificationのみ並列評価パネル可: FABER含め最大3系、多数決（2/3以上で合格）。差し戻し時は全評価者の指摘を統合して作り手へ渡す。通常はFABER単独で足りる、パネルは例外運用。
- loop7: verification差し戻し。run単位。固定基準で裁く。
