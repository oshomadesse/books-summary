# ドキュメント同期基準

`git push`する変更に応じて、次を確認する。

- **Node・Edge・Loop・Stateに触れる変更（最優先・必須）**: READMEの依存グラフ（mermaid）を同じpushで更新したか。依存グラフはHumanがグラフの詳細を監視できる唯一の場所であり、実態とズレた瞬間にHumanのValidation層が機能しなくなる。図が古いままのpushは差し戻し対象。
- **体験（入口・届くもの・操作手順）に触れる変更（必須）**: READMEの**体験グラフ**（mermaid）と「むずかしい言葉なし版」を同じpushで更新したか。依存グラフがシステム挙動の唯一の監視点であるのに対し、体験グラフは「しょーまが何をすると何が届くか」の唯一の監視点。ボタン・通知・入口が増減したのに図が古いままのpushは差し戻し対象。
- 機能追加・設計変更: `docs/更新記録.md`に追記したか。更新記録は追記専用とし、過去の行を書き換えない。
- 設計判断そのものの変更: `docs/設計記録.md`も更新したか。
- README: フォルダ対応表、エラー出口一覧が実態と一致しているか。
- メモリ: 今回の変更でメモリが古くなっていないか。判断基準は `~/.claude/rules/memory-hygiene.md` に従う（このファイルではない）。実体のないポインタ・index未掲載といった機械的な腐りは commit 直前にフック `memory-hygiene.sh` が自動で正すため、ここで見るのは読解が要るものだけ（完了したTODO、CLAUDE.mdとの重複、実態と食い違う記述）。
- 生成物のみのpush: 何もしない。
- 初回push前: `docs/設計記録.md` の 0〜9 に空欄（記入）が残っていないか。
